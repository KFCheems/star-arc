# 手感调参 · Feel Tuning

所有影响手感的数值都在 `src/const.js`。改完 `npm run build` 即可。
这份文档说明每个数字实际控制什么，以及往上调/往下调会发生什么。

---

## 轨道 / 捕获

| 常量 | 默认 | 作用 | 调大 | 调小 |
| --- | --- | --- | --- | --- |
| `orbitOmega` | 6.05 | 环绕角速度（rad/s） | 转得更快，窗口更难按准 | 更好按，但节奏变拖 |
| `captureRadius` | 96 | 能抓住星的最大距离 | 更容易接上 | 更容易飞空 |
| `orbitMin/Max` | 46 / 88 | 环绕半径范围 | 视野更散，预测线更长 | 更紧凑，更贴脸 |

`world.js` 通过 `CFG.orbitOmega` 读取这个值，只有一处定义，直接改 `const.js` 即可。

---

## 飞行

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `speedStart` | 352 | 起手飞行速度（px/s，已乘屏幕缩放） |
| `speedEnd` | 548 | 满难度时的速度 |
| `speedRampSeconds` | 110 | 从起手到满速用多少秒 |
| `steerRate` | 2.55 | 每秒最多转向多少弧度——**这是"飞行手感"最重要的数字** |
| `steerNear` | 0.42 | 靠近目标时保留多少转向力（防绕圈） |
| `wallBounce` | 0.82 | 撞墙后保留的速度比例 |
| `predSteps` / `predStride` | 26 / 0.028 | 预测线长度（26 × 0.028 ≈ 0.73 秒） |

`steerRate` 调大 → 飞行更像追踪导弹，几乎必定抓到下一颗星，难度下降。
调小 → 更像弹道，会错过目标，需要玩家自己算角度，难度上升但挫败感也上升。

---

## 共振弧（核心得分窗口）

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `pulseStart` / `pulseEnd` | 3.55 / 2.15 | 每几秒来一次「脉冲」，把所有弧临时加宽 |
| `pulseSpeed` | 690 | 脉冲扩散速度 |

弧的宽度（`arcW`，半角）默认 1.05 rad（约 60°），脉冲时临时升到 1.75。
60° 在 5.2 rad/s 下约等于 **0.20 秒**的窗口——紧，但可得。
想让新手更友好，把 `makeStar()` 里的 `arcW: 1.05` 提到 1.35。

---

## 得分

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `scoreTravel` | 0.045 | 飞行距离得分系数（乘倍率再乘 0.5） |
| `scoreMote` | 12 | 每颗光点 |
| `scoreResonance` | 62 | 每次 PERFECT 基础分（乘倍率） |
| `surgeAt` | [4,7,11,15,20,26] | 第几连击触发 SURGE |
| `surgeBonus` | 240 | SURGE 基础分（乘倍率） |

倍率 = `min(1 + streak, 20)`。所以 20 连击时每次 PERFECT 是 62 × 21。

---

## 难度

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `insetStart/End` | 0.062 / 0.168 | 星场左右边界内缩比例（压迫感来源） |
| `insetRampSeconds` | 84 | 内缩用多少秒 |
| `starFuel` | 3 | 一颗星能环绕多少秒 |
| 碎星数量 | `(runTime-11)/24 + 1`，上限 6 | 11 秒后开始出现碎星 |

**想更硬核**：`speedRampSeconds` 降到 70，`insetEnd` 提到 0.2。
**想更休闲**：`starFuel` 提到 4.5，碎星上限从 6 降到 4（改 `targetShards()`）。

---

## 打磨类（影响"手感"而非规则）

| 位置 | 常量 | 作用 |
| --- | --- | --- |
| `world.js` | `hitstop = 0.07` | PERFECT 时的顿帧时长 |
| `world.js` | `timeScale = 0.28` | PERFECT 后的慢动作强度（0.28 = 28% 速度） |
| `world.js` | `shake = 7 + min(12, streak)` | 震屏强度 |
| `const.js` | `slowmo` | 未使用，保留位 |
| `world.js` `updatePulse` | `s2.arcW = 1.75` | 脉冲时弧的加宽量 |

慢动作太拖 → `timeScale` 调向 0.45；顿帧太肉 → `hitstop` 降到 0.04。
震屏晕 → `shake` 上限从 22 降到 12（`const.js` 的 `shakeMax`，同时改 `world.js` 里的计算）。

## 调试

网址加 `?debug` 打开 FPS / 实体计数面板：

```
http://127.0.0.1:8123/?debug
```

改完跑一遍回归：

```bash
node build.mjs && node tools/shoot.mjs
```

它会用真实输入模拟一个会玩的人跑完整局，并断言控制台零报错。
重点看输出里的 `turns` 数组：如果 `streak` 长期卡在 0，说明窗口太窄或
`steerRate` 太低。

## 性能

帧耗时分层实测（390×844 @2x，Chromium）：

| 层 | 优化前 | 优化后 |
| --- | --- | --- |
| 星体 | 12.0 ms | 5.1 ms |
| 背景 | 6.6 ms | 0.6 ms |
| 星场边框 | 4.2 ms | 1.9 ms（缓存后仅剩呼吸线） |
| **全部图层** | **19.4 ms** | **11.0 ms** |

三处主要改动：

1. **星体整张烘焙**。光晕 + 球体 + 边缘光原本每帧每颗星新建 3 个径向渐变。
   现在按 (色相, 尺寸分桶) 烘焙成一张贴图，一次 `drawImage`。星体是固定的三种颜色，
   所以缓存命中率是 100%。
2. **星场边框按几何缓存**。内层网格、晕影、角标只在场地矩形变化时重建
   （键按 2px 量化，否则每帧的缓动漂移会让缓存失效）。
3. **星空批量绘制**。远层 190 颗星原本是 190 次 `fillRect`，现在按透明度分 4 桶
   合成 4 个 path。

注意：这些数字是在**无 GPU 的软件光栅化**下测的（headless Chromium 默认如此）。
打开 GPU 后全部图层是 **1.8 ms**。所以这里测的是余量，不是真机表现——
真机会更好。要复现：

```bash
node tools/_perf.mjs   # 需要先服务 dist/web
```
